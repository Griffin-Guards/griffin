Agents

Give your bot the wallet, not the vault. The agent key stays on its machine.

Set up

Four steps

  1. Open the app, connect your wallet, paste the agent's public key (or make one there), create.
  2. Sign a charter. Until you do, every agent move is turned back.
  3. Fund the vault, and give the agent key a little SOL for fees and proposal rent.
  4. Run the Griffin MCP server next to your agent. It proposes, asks Griffin and sends the release.

Local tools: griffin_status, griffin_send_sol, griffin_send_token, griffin_swap. Swaps ask Jupiter again without any DEX Griffin would not pass, so the route fits the charter.

{
  "mcpServers": {
    "griffin": {
      "command": "node",
      "args": ["griffin/agent/cli.mjs", "mcp"],
      "env": {
        "GRIFFIN_AGENT_KEY": "~/.griffin/agent.json",
        "GRIFFIN_WALLET": "<wallet from the app>",
        "SOL_RPC_URL": "<your RPC>"
      }
    }
  }
}

# or the CLI
node agent/cli.mjs status
node agent/cli.mjs send <to> 0.05
node agent/cli.mjs swap <inMint> <outMint> <baseUnits>
Hosted

API and read-only MCP

Base: https://griffinguard.fun. The hosted MCP at /mcp has griffin_check and griffin_policy, for agents that build their own Squads proposals.

CallWhat it does
GET /v1/griffinGriffin's vote key and the base program list
GET /v1/wallet/:multisigMembers, whether Griffin can guard it, the charter, recent verdicts
POST /v1/policy{ multisig, policy, nonce, signature }, signed by the owner
POST /v1/guard{ multisig, index } → verdict, and the release transaction when passed
GET /v1/feed, /v1/statsThe gate: latest verdicts and counts
