What reverts

These are the module's own errors. They fire on chain, so they hold even if Griffin's server were wrong or its key leaked. Griffin explains each one in words before the agent ever sends.

NotRecipient

ETH or a token transfer to a wallet you did not list.

OverMove

More ETH or more of a token than one move may take.

OverDay

Today's total would pass the daily limit (UTC day).

NotAllowed

A contract you did not list, an approval of an unlisted spender, transferFrom, permit.

SelfCall

A call to the Safe or the module, which would act as the owner: add an owner, rewrite the charter.

BadSignature

No Griffin signature, someone else's, an old nonce, or a move edited after signing.

NotAgent

Anyone but the agent key the Safe named.

Expired

Griffin's signature is good for ten minutes.

The contract

Read it yourself

No owner, no admin, no upgrade. Once deployed nobody can change it. Each Safe writes its own charter with its own transaction, and the whole charter is in the CharterSet event.

For agents

Give it the wallet, not the vault

  1. In the app, connect your wallet and make a Safe: you as owner, the agent's address, the charter. One transaction.
  2. Fund the Safe. Give the agent key a little ETH for gas.
  3. Run the GRIFFIN MCP server next to your agent. For each move it asks Griffin, then sends execute itself.

Tools: griffin_status, griffin_send_eth, griffin_send_token, griffin_call. Hosted MCP at /mcp.

{
  "mcpServers": {
    "griffin": {
      "command": "node",

      "env": {

Limits

  • Inside a listed contract, value can still be lost within your limits, for example a bad price inside the slippage the agent chose. Keep limits to what you'd accept losing in a day.
  • Daily limits reset at 00:00 UTC.
  • If Griffin's server is down, agent moves wait. You can remove Griffin and let the charter alone decide, or disable the module. Your own Safe never waits on anyone.
  • GriffinModule has not been audited. Start small.
